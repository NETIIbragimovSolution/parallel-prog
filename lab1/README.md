# Лабораторная работа: параллельное численное интегрирование

**Вариант 1.** Функция: f(x) = (1+x) / (2+3x)², интервал интегрирования [1; 3].
**Метод:** левых прямоугольников: I ≈ h·Σf(a + i·h), i = 0..n-1, h = (b-a)/n.

Реализовано два способа распараллеливания:

- **POSIX threads** (`pthread_create`/`pthread_join`)
- **std::thread**

Диапазон индексов `[0, n)` делится на непрерывные блоки — по одному на поток,
каждый поток считает свою частичную сумму, результаты потом суммируются и
умножаются на h. Гонок данных нет: каждый поток пишет только в свою ячейку.

## Сборка и запуск

```bash
g++ -O2 -std=c++17 -pthread main.cpp -o integrate
./integrate
```

Программа запросит:

1. `n` — количество разбиений (шаг h = (b-a)/n);
2. количество потоков для основного расчёта;
3. максимальное количество потоков для тестирования производительности.

Функция очень лёгкая (несколько арифметических операций), поэтому для
заметного эффекта от многопоточности берите большое `n`, например `10^8`.
На маленьких n накладные расходы на создание потоков могут перевесить выигрыш.

Вывод программы:

- таблица тестирования по потокам (1..max) для POSIX и std::thread — время,
  результат, ускорение и эффективность относительно однопоточного запуска;
- CSV-файлы `results_posix.csv` и `results_stdthread.csv` с теми же данными;
- сравнение "многопоточность vs однопоточность" для выбранного числа потоков;
- точное значение интеграла (аналитически), фактическая погрешность и
  проверка точности 10⁻²/10⁻³ из варианта.
